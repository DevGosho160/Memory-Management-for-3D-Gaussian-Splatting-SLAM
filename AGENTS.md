# Research workflow

- Before substantial work, read `docs/PROJECT_CONTEXT.md`, `docs/CODEX_HANDOFF.md`, and `docs/RESEARCH_PLAN.md`.
- Inspect current source before trusting documentation. Ground truth: code/reproducible results > git history > handoff/current docs > research plan > proposal > chat/assumptions.
- Distinguish CONFIRMED facts, INFERENCE/hypotheses, PLANNED functionality, and OPEN QUESTIONs. Defined functions and TODOs do not prove integration or execution.
- Coordinate with the documented team responsibilities; unfinished infrastructure is not automatically Phillip's assignment.
- After substantial implementation or experiments, update `docs/CODEX_HANDOFF.md` with the revision, validation, artifacts, decisions, and next three actions. Update stable context only when facts change.
- Preserve upstream behavior as an explicit comparison. Do not claim a Gaussian-count cap or a per-process allocator limit proves an application-wide GPU-memory budget.
